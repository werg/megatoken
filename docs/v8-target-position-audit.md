# V8 executed target positions

The target-presence census answers which logical and physical records contributed
to optimizer updates. This additional audit checks the exact eligible token
positions and public categorical supports for the ordinary prepared UTF-8 text
path. It does not reuse the target planner to derive its expected labels.

## Independent truth and actual selections

The independent side reads immutable physical records after the existing source,
contract, tokenizer and prepared-data admission gates. Recorded emitted IDs take
precedence over cached IDs; otherwise the pinned byte codec encodes the payload.
The IDs must spell the exact payload. Their byte pieces independently reconstruct
token boundaries. A token is eligible only when its full byte interval lies in a
free span, when spans are provided, and its recorded emission mask also permits
it, when an emission mask is provided. Repeated token values retain distinct
coordinates. Observation records receive no target credit.

The execution side records the actual tensor indices passed to the decoder's
gather operation and the actual labels and alphabet mask used by lexical cross
entropy. Prior prediction and reconstruction receive separate receipts. It also
records the actual local cross-entropy labels and public supports for length,
format and terminal decisions, and the actual modality labels and capability
masks. It stores indices, labels, booleans, public supports and input hashes;
it does not store activations, predictions, logits or routing assignments.

The audit compares these two sides before an optimizer update. Its cumulative
history advances only after that update succeeds, and is sealed into the normal
checkpoint. Exact resume requires the matching history and objective identity;
checkpoint metadata must independently name the same history digest and global
step. An explicit stage transition checks and archives the same bound history.
An older checkpoint without positional receipts cannot acquire retrospective
position credit. This is a direct pre-release format change.

An explicit training-stage transition begins a new census at the existing global
step and archives the complete prior stage's sealed receipts. The new stage's
counts start at zero. Ordinary resume still rejects an objective change; only the
already-supported explicit stage transition creates a fresh objective scope.

## Coverage boundary

The supported profile is prepared plain-text V8 data without structured tool
schemas or recorded native action tapes. Public text length, format and terminal
supports are reconstructed from the configured generated capacity, model capacity
and physical part boundaries. Modality support comes independently from prepared
event settings and installed rendering capabilities. These categorical decisions
are reported separately from lexical positions. In particular, modality is a real
positive-weight objective even though the earlier per-record target-plan census
did not enumerate its grouped-execution denominator.

Routing regularizers operate on internal hidden rows; the physical payload does
not independently determine those rows. During training, the existing router
balance recorder now contributes per-selector counts of the internal rows it
actually routed, plus separate expert-assignment counts. Adapter controllers can
choose several experts for one context row, so these counts are not interchangeable.
The checkpoint retains only the aggregates and the number of optimizer updates
with a router-count receipt; it does not retain expert IDs, contexts or individual
assignment lists.
This provides actual router-row accounting, while **router internal position
coverage remains unmeasured** because the prepared-data oracle cannot independently
reconstruct hidden router rows. The
same boundary applies to latent representation coordinates, transducer/retrieval
losses, media masks and structured-action field/copy/placement masks. Unsupported
targets are explicitly unmeasured and cannot satisfy complete text-position
qualification.

The existing completed 348-update campaigns predate these receipts. They retain
their exact target-presence, window-occurrence and denominator evidence, but
their token/mask-position coverage remains unmeasured. A new full current-contract
run is required before claiming complete positional coverage for the 48-source,
696-logical-target, 720-physical-target population. Implementing or preparing the
audit does not establish that exposure or learned semantic quality.

## Validation progress

- Actual tiny CPU decoder execution leaves loss numerators, denominators and raw
  input gradients exactly unchanged when the observer is enabled.
- Focused controls reject omitted, invented, shifted and duplicate positions,
  wrong token labels, changed alphabet masks, altered categorical supports,
  missing decisions and resealed malformed checkpoint metadata.
- The ordinary tiny optimizer/checkpoint/fresh-process-resume test runs with the
  observer active; both saved and resumed histories contain actual receipts. The
  ordinary lifecycle collector independently checks this observed subset and
  retains its partial population comparison without requiring the full fit.
- The complete prepared-record comparison independently enumerates policy
  targets without the window iterator or target planner. Each distinct physical
  target must appear once in the actual receipts. Controls reject even a jointly
  shifted prepared-plan/execution mask whose counts and repeated token labels
  still agree, and a duplicated target that both older accounting paths repeat.
- The dedicated full qualification driver requires the independent comparison;
  historical target-only evidence cannot satisfy it. The frozen implementation
  passed a complete four-target actual fixture run, then an actual explicit stage
  transition; separate fresh-process resume evidence correctly remains a partial
  three-of-four-target subset. See [retained bounded evidence](evidence/v8-target-positions-2026-11-22/README.md).
  The router balance recorder now contributes per-selector internal-row counts
  to optimizer position history, and resume rejects checkpoint metadata whose
  digest or global step does not bind that history. Focused actual optimization,
  resume, stage transition and router-count controls cover these checks. No new
  full 348-update run has been launched for this audit yet.
